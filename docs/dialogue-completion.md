## 文件与来源字段

- `server/content/source/daily-200-original.json`：补全前的正式清单快照，核对原有台词使用，不是可导入文件。
- `server/content/source/daily-200-completions.json`：补写输入与来源映射，不是可导入文件。
- `server/content/daily-200.json`：可导入的完整合集。只含业务需要的内容与角色，不把审计字段传给小程序。
- `docs/dialogues-completed.md`：由相同数据生成的全量中英文阅读稿。

来源映射中的 `sourceParagraph` 是 Word 正文顶层段落的 1 起始编号，用于找到原文空 AI 标记。`originalParagraphs` 保存原有中英文所在的两个段落；`afterSourceKey` 指向紧邻前面的原有台词，AI 开场时为 null。新增 sourceKey 在首次补写时分配，后续改台词仍保留，不能按显示顺序重新计算。

`AI` 表示补写角色和来源，不代表原视频中确实说过这些话。三集样例风格由用户确认；全量补写经过上下文编写与结构核对，尚未经用户逐句审阅或原视频校验。应用继续把英文称为“参考英文”，不作为唯一标准答案。

## 编写和校对取舍

- 回复按整集内容承接前后文，保留原句中的口语、玩笑和角色扮演。没有可核实的照片信息时，不补人物身份、植物品种、地点等具体事实；图片场景继续使用原有文字提示。
- 第 3 集水果样例按已查看的图片补写，遮挡的草莓不强行给出数量。第 1 集头像不推断具体外观。
- 原有事实性说法不做静默重写。例如第 61 集器官休息说法、第 105 集饮酒耐受、第 134 集空调设定、第 167 集紫外线及晚霞判断、第 180 集骨头汤、第 188 集考拉睡眠原因，在 AI 回应中作温和澄清。
- 第 178～186 集涉及角色的身体不适，AI 不凭对话下诊断、不提供具体用药剂量；对重复用药、呼吸困难、脱水等情境采用适当的提醒。第 181 集不承诺晒伤后一夜变白。
- 第 166 集极端天气以当地官方预警为准；第 196、198 集机场和出入境情境不把原文的时效性说法推广成普遍现行规则。
- 第 194 集传闻使用待核实语气；第 199 集“世界第一”保留为原角色的主观评价。

这些是学习对话的编辑记录，不是医学、法律、旅行或气象事实资料；未对原有全部台词做事实核验或重译。

## 验证与升级

`content:build` 仅从快照和补写输入生成正式清单、阅读稿；`content:check` 验证两者一致，均不连接数据库。结构检查包括原文完整保留、来源位置唯一、AI 插入位置正确、角色范围、条目顺序连续、总数和稳定标识。

导入替身测试验证了新增 AI、重排原句、BIGINT 精度、保留原 ID、重复导入幂等和拒绝隐式恢复。迁移替身测试验证只读预览、新增字段、重复执行跳过、异常结构拒绝和迁移互斥。它们不是实际 MySQL 或微信真机验证。

已有库先执行 `db:speaker:plan`，审阅后用 `db:speaker:migrate` 增加角色字段，再审阅 `content:plan` 并使用 `content:import --accept-changes`。完整测试/生产命令及部署顺序见仓库 README 的“已有数据库升级对话内容”。本轮未连接数据库、执行 DDL/DML、部署或发布小程序。
