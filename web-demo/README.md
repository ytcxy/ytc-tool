# 第 5 集网页验证样例

在仓库根目录运行 `node web-demo/serve.mjs`，打开 http://127.0.0.1:4175 。无需依赖安装、数据库或环境凭据；端口可通过 WEB_DEMO_PORT 指定。

页面沿用拾句英语的配色，英文来自用户提供的第 5 集截图，中文为人工风格翻译；共 17 个发言回合，截图同一行的奥利、欧文分别拆开，末句保留奥利与丹尼共同发言。这里的三个人物不映射为正式清单的“你 / AI”。不修改已有合集、音频或学习进度。

视频使用用户此前给出的 bvid/aid/cid/p，尚未确认其是否对应截图内容。不能从“第 5 集”推断 p=5，因此保留给定的 p=1。按用户要求，17 句暂用 0、5、10……80 秒作为演示起播时间，明确标记为演示时间，不表示真实对白位置。首次点击加载视频后连接 B 站，不下载或代理媒体。

## 验证

1. 点击加载视频，人工确认是否有声音、画面，是否对应第 5 集。
2. 展开“播放验证与时间校准”，测试 0、15、30 秒起播（须小于视频时长），记录实际位置及等待时间。
3. 默认点击中文即可按演示时间请求起播。勾选逐句校准，可填入秒数或 mm:ss 手动调整；留空设置可取消该句播放，刷新恢复默认演示时间。
4. 查看单句 / 全部英文展开收起，检查 375px 手机及桌面布局。
5. 用户批准部署后，将 index.html、style.css、app.js、dialogue.js 一起部署到 HTTPS 静态目录。不要上传本地其他文件；静态页面相对路径支持子目录。若站点已有 CSP，需允许 frame-src https://player.bilibili.com，而不是关闭所有 CSP。
6. 将实际 HTTPS 链接手动发到微信，分别记录手机系统、微信版本、网络、B 站登录状态、加载成功与否、手动播放、时间跳转、全屏退出和重复播放结果。没有实测的系统标为未验证。

iframe 跨域，load 事件只能说明框架载入，不能作为视频成功或时间跳转成功的证据。公开参数 t 是初始时间；每次切换重建 iframe，可能重新缓冲。没有句末自动暂停、真实播放进度高亮或跨页面学习进度同步。自动播放受微信与浏览器限制，必要时手动点击 B 站播放器。

本地地址仅用于本机开发，不是手机可访问的公网链接。尚未公开部署、没有微信真机验证。

## 本轮验证记录

- Node.js 24：三个脚本语法检查通过；时间解析检查覆盖 0、分秒、小数、负数、非法秒位、空值、超限及非法文本；播放器地址和给定 cid、t 参数检查通过。
- Codex 内置浏览器：17 个发言回合正常渲染，全量英文展开通过；初版第一句临时设置 0:15 后启用播放，并生成 t=15 的 iframe。该时间仅用于验证交互，刷新已清除。
- 375px 视口检查没有横向溢出，桌面双列 / 手机单列布局已检查。
- B 站 iframe 在本轮内置浏览器显示“无法播放媒体”，原因未确定。因此视频实播、准确起播、内容是否对应第 5 集均未验证成功，不能声称微信可播放。
